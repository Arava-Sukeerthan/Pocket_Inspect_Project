## How the queue was built

- **Coded values** (characteristics, metrics, notes) come from the current [`papers.csv`](papers.csv) (31-column schema, commit `9ebbf89`).
- **Relevance class:** `papers.csv` has **no `relevance_class` column**. The A–E classes exist only in [`audit_report.csv`](audit_report.csv) (first-pass audit, 2026-10-02). That file states the classes are the auditor's proposal for researcher review, and no later step changed them. The queue reads the class from `audit_report.csv` at build time and joins it to the current `papers.csv` by `paper_id`. **Researcher decision:** should the relevance class become a `papers.csv` column? That would be a schema change and is not done here.
- **Queue rule:** every class-A paper (17) plus P013 (class D). Priority is **HIGH** for all 18 queued papers. All other papers are **not in the current queue**.
- **Thematic groups:** the group in `notes`, plus the search that actually retrieved the paper (from [`search_log.md`](search_log.md)) where it differs.
- **Issues:** taken from `audit_report.csv`, the Step 8.3 recoding flags ([`recoding_report.md`](recoding_report.md)), and `Unknown` values relevant to the paper. Fields not listed should still be checked using the template.
